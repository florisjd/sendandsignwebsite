How it works

SharePoint in, SharePoint back.

1 · Inside your tenant

Send from a library

Staff pick a PDF or interactive HTML proposal they can already open (save Office files as PDF first), add 1 to 20 recipients and send the invitation from their own Microsoft 365 mailbox. Parallel or sequential routing is available from Tier 2; in a sequence, later turns are emailed by the Signing Bridge.

2 · Outside SharePoint

Client signs with no login

The signer opens a single-use link, enters a 6-digit email code, accepts electronic consent, then draws, types or uploads a signature. IP address, browser, consent fingerprint and UTC and AWST times are recorded.

3 · Back in SharePoint

Signed copy filed beside the original

A certificate and audit trail are added. Your web part checks the file’s fingerprint and saves it to the same folder using the signed-in user’s permissions. Everyone receives a completion email (PDF attached up to 10 MB; HTML as a 7-day download link).

Built for simple commercial contracts under s 10 of the Electronic Transactions Act 1999 (Cth) and the State and Territory equivalents. Not for deeds, Corporations Act s 127 executions, wills or witnessed instruments. Compliance details.

Option B · PnP.PowerShell instead

Microsoft requires Connect-PnPOnline to use an app registered in your tenant. Replace <your-tenant> and <your-pnp-entra-app-id>, and read the script before you run it.

# Requires PowerShell 7+ and PnP.PowerShell (Install-Module PnP.PowerShell -Scope CurrentUser)
# First time using PnP.PowerShell? Register an app once:
#   Register-PnPEntraIDAppForInteractiveLogin -ApplicationName "PnP PowerShell" -Tenant "<your-tenant>.onmicrosoft.com" -Interactive
$pnpClientId = "<your-pnp-entra-app-id>"
$adminUrl = "https://<your-tenant>-admin.sharepoint.com"
Connect-PnPOnline -Url $adminUrl -Interactive -ClientId $pnpClientId

$pkgPath = "$env:TEMP\spfx-send-and-sign.sppkg"
Invoke-WebRequest -Uri "https://sign.sendandsign.online/downloads/spfx-send-and-sign.sppkg" -OutFile $pkgPath
Add-PnPApp -Path $pkgPath -Scope Tenant -Publish -SkipFeatureDeployment -Overwrite

$pending = Get-PnPTenantServicePrincipalPermissionRequests
$wanted = @("User.Read", "Mail.Send", "Sites.Read.All", "People.Read", "Envelope.ReadWrite")
foreach ($req in $pending) {
  if ($wanted -contains $req.Scope) {
    Approve-PnPTenantServicePrincipalPermissionRequest -RequestId $req.Id
  }
}

Send & Sign uses one central SendAndSignTracking list across your sites and Teams.

1 · Central hub

The first Site Administrator setup saves your hub site address on the Signing Bridge. Change it with Admin → Set as Central Hub Site.

2 · More SharePoint sites

Web parts added to other sites connect to the hub’s list. To keep a department separate, set Central Tracking Site URL in that web part’s properties.

3 · Microsoft Teams

In Manage apps, select spfx-send-and-sign-client-side-solution and click Sync to Teams (or Add to Teams). Add SendAndSign from Teams → Apps → Built for your org or as a channel tab.

4 · Optional HR confidentiality

Staff who send need Contribute on the tracking list. To limit what they see, open List Settings → Advanced Settings → Item-level Permissions and choose Read items that were created by the user and Create items and edit items that were created by the user. Site Owners and SharePoint Administrators still see everything.

For your security review

Data handling and location.

Your SharePoint stays the permanent record. While an envelope is out for signature it passes through the Signing Bridge, which is not hosted in Australia.

Item on the Signing BridgeWhen it is deleted
Original document and later-turn attachmentsImmediately once your SharePoint confirms the signed copy; at the next hourly clean-up if declined, cancelled or expired; kept up to 90 days if never saved back
Signed copy7 days after confirmed save-back to SharePoint
Envelope details and audit trail90 days after the envelope finishes
Signer sessions30 minutes
Encrypted backups14 days

Protection

TLS 1.3 in transit and AES-256-GCM encryption for each envelope. Signing links, session IDs, download links and one-time codes are stored only as hashes.

Hosting

The bridge and its email service run on Hostinger outside Australia. We don’t claim Australian hosting. Full signing bridge disclosure.

AI is optional

Core signing never uses AI. Only when a user runs Transform with Claude is the chosen document sent to Anthropic in the United States. What is sent and kept.

Upload and choose Replace

Troubleshooting

Quick fixes

“The requested permission isn’t valid”

Consent isn’t complete. A Global Administrator completes the consent page, then in API access press F5 and click Approve.

TENANT_NOT_ONBOARDED or a Setup Doctor prompt

Click Connect Microsoft 365 on the Setup Doctor card, or open the Setup Hub, as a Global Administrator.

AADSTS65001 or a missing esign-api token

A permission is still pending. In SharePoint Admin Center → Advanced → API access approve esign-api / Envelope.ReadWrite and the four Microsoft Graph scopes.

ADMIN_ROLE_REQUIRED when entering a licence key

Use a Global or SharePoint Administrator account. If newly promoted, sign out and in again, then enter the key under Admin → Licence & plan.

A large PDF won’t upload

Compress it to 18 MB or less before sending.

Status is Signed but the signed file isn’t in the folder yet

A user with write access to that folder needs to open the Send & Sign dashboard and click Refresh.
