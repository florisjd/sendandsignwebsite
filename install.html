For clean audit compliance, Send & Sign is designed around one central master SendAndSignTracking list shared by every page, site and Team.

1 · Automatic central hub pinning

The first time a SharePoint Administrator provisions Send & Sign on your primary site (e.g. /sites/SendAndSign), the tenant's Central Hub Site URL is saved on the Signing Bridge. Change it at any time via Admin → Set as Central Hub Site.

2 · Adding Send & Sign to more sites

Web parts on other sites connect to the hub's master list automatically (falling back to SharePoint Search discovery if no hub is pinned) instead of creating duplicate lists. To deliberately isolate a department site, set Central Tracking Site URL in that web part's property pane.

3 · Publish to Microsoft Teams

In SharePoint Admin Center → More features → Apps → Manage apps, select spfx-send-and-sign-client-side-solution and click Add to Teams (or Sync to Teams). Then add SendAndSign from Teams → Apps → Built for your org or as a channel tab. It syncs with your central hub.

4 · Permissions & confidentiality on the master list

Give staff who send envelopes Contribute on the master SendAndSignTracking list.

Optional, for HR or executive privacy: in List Settings → Advanced Settings → Item-level Permissions, set Read items that were created by the user and Create items and edit items that were created by the user. Staff then see only their own envelopes, while Site Owners and SharePoint Admins still see all of them for audit and archiving.

Security & architecture

Lifecycle

Upgrading or removing

Upgrade

Upload the new package and choose Replace

Upload the new spfx-send-and-sign.sppkg to Manage apps and choose Replace / Overwrite. Solution and web part IDs are preserved, so existing pages, tracking history and signed files stay intact.

Disable or uninstall

Your data stays in your tenant

Select spfx-send-and-sign in Manage apps and click Disable or Delete. The web part stops running on every site immediately; originals, signed copies, tracking lists and audit archives all remain in SharePoint.
