## 1. What Is a `.sppkg` File?

A SharePoint Framework package (`.sppkg`) is simply a standard **ZIP archive** (Open Packaging Conventions format) generated by Microsoft's official **SPFx `1.24.1`** and **Heft** build toolchain.

**You do not have to take our word for it:** any IT Administrator can rename `spfx-send-and-sign.sppkg` to `spfx-send-and-sign.zip`, extract it, and inspect every single XML and JavaScript file before uploading it to SharePoint.

## 2. Exact Contents Inside `spfx-send-and-sign.sppkg`

| File / Folder Inside `.sppkg` | Purpose |
|---|---|
| `AppManifest.xml` & `[Content_Types].xml` | Standard Microsoft manifest declaring the solution ID (`d7b3c67e-6a71-4e6e-9ff9-1964534f95fd`), version, the 3 delegated Microsoft Graph scopes (`User.Read`, `Mail.Send`, `Sites.Read.All`) and the delegated Signing Bridge scope (`esign-api` / `Envelope.ReadWrite`). |
| `feature_*.xml` & `WebPart_*.xml` | Registers the **Send & Sign** client-side web part (`e753ff65-67e6-4f92-9663-9579f8d1a026`) so it appears in the SharePoint modern page web part picker. |
| `ClientSideAssets/send-and-sign-web-part_*.js` | The compiled React `18.3.1` + Fluent UI browser bundle for the dashboard, document picker, and archive controls. |
| `ClientSideAssets/*.LICENSE.txt` | Open-source licence notices for bundled UI libraries. |
| `ClientSideAssets/SendAndSignWebPartStrings_*.js` | Localised UI labels. |
| `ClientSideAssets/*_color.png` / `*_outline.png` | Web part icon assets. |

### What Is **NOT** Inside the Package
- **Zero server-side executables, `.dll` files, or SharePoint Farm Solutions** (cannot run on Microsoft's SharePoint servers or crash your farm).
- **Zero external runtime script downloads** (all assets are self-contained inside the `.sppkg`).
- **Zero embedded secrets, API keys, or passwords.**
- **Zero telemetry trackers or third-party ad/analytics scripts.**

## 3. How We Guarantee the Package Is Safe for Your SharePoint Tenant

### 1. Strict Client-Side Sandbox & 2026 SharePoint CSP Compliance
- Built with `includeClientSideAssets: true` on **SPFx `1.24.1`** and **TypeScript `5.8` (`strict: true`)**.
- All JavaScript runs inside the signed-in user's browser sandbox under Microsoft SharePoint Online's strict Content Security Policy (CSP): zero `eval()`, zero inline `<script>` tags, zero external CDN script injection, and zero mutation of SharePoint's host page DOM or CSS.

### 2. Zero Privilege Escalation (User-Context Only)
- The web part operates strictly under the **currently signed-in Microsoft 365 user's identity**.
- It can only browse SharePoint sites, folders, and files that the user already has permission to view—it cannot bypass SharePoint permissions or access restricted sites.
- Its Microsoft Graph site permission (`Sites.Read.All`) is **read-only**; it cannot delete or overwrite sites or libraries via Graph.
- Its only other scope, `esign-api` / `Envelope.ReadWrite`, is accepted solely by the Send & Sign Signing Bridge and only for your own tenant's envelopes; it grants no SharePoint or Graph access.

### 3. Non-Destructive File Handling & Zero-Script HTML Safety (`v2.0`)
- Original contracts (`.pdf`, `.docx`, `.xlsx`, `.pptx`, `.rtf`, `.odt`, `.html`) are **never modified**. Signed outputs are saved as a separate file (`{OriginalName}_Signed.pdf` or `{OriginalName}_Signed.html`) in the same folder.
- Macro-enabled Office files (`.docm`, `.xlsm`, `.pptm`) are automatically blocked before conversion.
- **Interactive HTML proposals (including Claude MCP drafts)** are strictly sanitized on the Signing Bridge (`htmlSanitizer.ts`: all `<script>`, inline `on*` event handlers, `javascript:` URLs, `<iframe>`, `<object>`, `<embed>`, and external CSS `@import`/`url()` are stripped) and rendered inside a zero-privilege `<iframe sandbox="">` in the external portal—so zero executable JavaScript ever runs inside SharePoint or the signing portal.

### 4. Automated Supply-Chain & Quality Gates
Every release build passes:
- **Zero AGPL/GPL/SSPL Licence Gate:** Clean-room MIT/Apache-2.0 compatible dependencies only.
- **Automated TypeScript, ESLint & Unit Tests:** Verified before `.sppkg` packaging (`36/36` SPFx Jest tests, `62/62` Signing Bridge tests, `11/11` Domain tests, `7/7` Audit tests, and `2/2` MCP Connector tests passing as of `v2.0.0.0`).
- **Gitleaks Secret Scanning & CycloneDX SBOM:** Ensures zero leaked credentials and full Software Bill of Materials transparency.

### 5. Instant, Zero-Impact Removal
- If you ever disable or remove `spfx-send-and-sign.sppkg` from your **Tenant App Catalog**, the web part stops running immediately across all pages.
- **100% of your original files, `{OriginalName}_Signed.pdf` / `{OriginalName}_Signed.html` copies, tracking lists (`SendAndSignTracking`), and SHA-256 audit archive ledgers remain safely in your SharePoint tenant.**

## 4. 5-Minute IT Verification Checklist (For Customer Admins)

Before rolling out broadly, your IT team can verify safety directly:
1. **Inspect the Archive:** Rename `spfx-send-and-sign.sppkg` → `.zip`, open `AppManifest.xml`, and verify only `User.Read`, `Mail.Send`, `Sites.Read.All` and `esign-api` / `Envelope.ReadWrite` are requested.
2. **Malware Scan:** Scan the `.sppkg` with Microsoft Defender / your endpoint AV.
3. **Review API Access:** After uploading to the App Catalog, review the pending permissions in **SharePoint Admin Center → Advanced → API access** before clicking Approve.
4. **Pilot on One Isolated Site:** Create a dedicated test site (e.g. `/sites/SendAndSign`), add the web part there first, and verify that `SendAndSignTracking`, `SendAndSignSettings`, and `SendAndSign_Archive` are created cleanly inside that site only.
