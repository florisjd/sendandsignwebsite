Signer verification

Three layers, chosen per envelope.

Most e-signature tools send the signing link and the code to the same inbox, so whoever controls that inbox, whether an attacker, an assistant or a shared accounts@ team, can sign. Every Send & Sign envelope starts with a single-use link and an emailed code. For agreements where email alone isn't enough, add an access code sent another way. Returning signers can verify with Face ID, Touch ID or Windows Hello.

In Williams Group Australia Pty Ltd v Crocker [2016] NSWCA 265, a person was not bound by an electronic signature that could not be shown to be theirs. How Send & Sign meets the Electronic Transactions Act.

Layer 1 · Always on

Single-use link and 6-digit email code.

Every envelope uses a 256-bit single-use link, stored only as a SHA-256 hash, together with a mandatory 6-digit code emailed to the signer.

Nothing shown before the code

The signing bridge withholds the PDF or interactive proposal until the signer has entered their code.

Brute-force lockout

Five wrong codes lock verification permanently (HTTP 423) and alert our operations team in real time. Resends have a 30-second cooldown.

Layer 2 · Optional per envelope

An access code that never travels by email.

For commercial agreements, HR contracts, NDAs and personal guarantees, tick Require out-of-band Access Code (2FA) in the SharePoint Send dialog. The signer then needs something only you gave them, delivered another way.

1

Generate or set a code

Click Generate PIN for a random 6-digit code (for example 482-915), or enter a private reference of 4–32 characters such as a matter or account number. Add an optional hint that isn't secret.

2

Kept out of email

The code is never put in the invitation, reminders or your SharePoint tracking list. The signing bridge hashes it straight away with scrypt and a random per-recipient salt, inside the AES-256-GCM encrypted envelope.

3

Share it another way

Right after sending, SharePoint shows a share card: copy the message, open a pre-filled Microsoft Teams chat, or send it by SMS or WhatsApp.

4

Locked until verified

Even someone with full access to the signer's inbox who passes the email code can't view or sign (HTTP 403) without the access code. Five wrong attempts lock it (HTTP 423) and raise an alert.

Hints that can't leak the code

Send & Sign blocks any hint that contains the code itself.

Prompted for guarantees

Documents that mention a "personal guarantee" or "guarantor" get a recommendation to turn on the access code before sending.

Layer 3 · Passkeys

Face ID, Touch ID and Windows Hello, bound to our signing site.

Send & Sign supports W3C WebAuthn / FIDO2 passkeys, so signers can verify with the biometrics already built into their iPhone, iPad, Android phone, Mac or Windows PC.

Verify once, then one tap

  • First document: the signer verifies with the email code (and the access code, if set), then clicks Save Passkey. A passkey can't be saved until verification succeeds.
  • Every document after that: a Verify with Passkey button at the top of the signing portal completes verification in one tap.
  • Desktop without biometrics: the browser shows a QR code to scan with their phone, or they can use the email code and access code instead.

Phishing-resistant

Every passkey is bound to sign.sendandsign.online. On a lookalike site, the browser refuses to use it.

No biometrics stored

Fingerprints and face data never leave the signer's device. We store only a public key and a signature counter, keyed by a one-way SHA-256 hash of the signer's email address. No plaintext emails are kept in the passkey store.

No email-only reset

If a signer loses their phone, someone with access to their email can't reset the passkey. Only the signed-in sender in SharePoint can allow a one-time fallback for that envelope.

Audit trail and certificate

Every check, recorded and chained.

Each verification event is hash-chained with RFC 8785 (JCS) canonical JSON and SHA-256, and printed on the sealed A4 Certificate of Electronic Signature & Audit Trail (and the sealed HTML certificate), with UTC and AWST times in DD/MM/YYYY format.

Questions from IT and legal

Common questions.

Do signers need a Microsoft 365 account or an app for the access code or passkeys?

No. Both work in Safari, Chrome, Edge and Firefox on phones and computers, with no guest accounts and nothing to install.

Does Send & Sign store fingerprints or Face ID data?

Never. Biometric checks happen inside the secure hardware of the signer's own device. We store only a public key, indexed by a SHA-256 hash of the signer's email address.

Do the access code or passkeys cost extra per envelope?

No. Both are included at $0 per envelope on every Send & Sign plan.

What if a signer uses an office PC without a fingerprint reader or camera?

The browser shows a passkey QR code they can scan with their iPhone or Android phone. Or they can verify with the email code and the out-of-band access code.

What if a signer gets a new phone and loses their passkey?

They let the sender know. The sender, signed in to SharePoint, can allow a fallback to the email code and access code for that envelope, so nobody with only email access can get around the passkey.
